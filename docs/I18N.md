# tokaSigns 多語系（I18N）

使用共用套件 `dev.toka:tokaI18n:0.1.0`（內嵌並 relocate 到 `dev.toka.signs.internal.i18n`）。目前只有繁體中文 `zh-TW`，語言由 `config.yml` 的 `language` 決定。

## 已抽出的 key

共 **71** 個 key（`src/main/resources/lang/zh-TW.yml`）。

| 區 | 數量 | 內容 |
|---|---|---|
| `cmd.sign.*` | 7 | 指令簡述、總用法、`set`／`inspect`／`check`／`refresh`／`jobs` 的用法 |
| `help.sign` | 1（23 行） | `/sign help` 全部說明，單一 YAML 清單，每行 `權限標籤|內容` |
| `msg.*` | 11 | 玩家與指令回應、維護工作訊息 |
| `err.*` | 28 | 錯誤、拒絕、用法錯誤；`err.ex.*` 為例外訊息（不含前綴）；`err.input.*` 為四行輸入檢查結果 |
| `ui.*` | 7 | 編輯表單標題與輸入框、狀態牌（type 41）牌面四行 |
| `log.*` | 10 | 後台文字 |
| `status.*` | 7 | 是／否、未就緒、點選模式名稱（複製／貼上／編輯／功能設定） |

程式中不再有中文字串字面值（註解與測試除外）。`yes`／`no` 在 YAML 會被讀成布林值，所以 `status."yes"`、`status."no"` 的 key 加了引號。

## 每個指令的 help 位置

`/sign help`（別名 `/signs`）→ `help.sign`。清單每行格式 `標籤|內容`：`*` 所有人、`<操作>` 需要 `tokaSigns.<操作>`、`p:<操作>` 只給遊戲內玩家、`type.<ID>` 需要 set 權限加該類型權限且 provider 已就緒。涵蓋子指令：help、status、inspect、check、refresh、jobs、jobs cancel、`--force`、edit、copy、paste、cancel、set，以及直接填寫四行的各類型格式（10、11、31、32、33、41）。

## 顏色套用對照

| 位置 | 套用 |
|---|---|
| 玩家訊息前綴 | `§7[告示]§r `（全插件固定） |
| 一般文字 | `§b`；變動值（數量、ID、工作編號、名稱）`§a${n}§b` |
| 錯誤／拒絕／用法錯誤 | `§c`（用法本身 `§e`） |
| 警告（未先複製） | `§e` |
| 成功（設定完成、操作完成） | `§a` |
| help | 標題 `§6§l`，指令 `§e`，分隔 `§7-`，說明 `§b`，補充 `§7` |
| 後台 log | 不加方括號；文字 `§b`、數字 `§a`、警告 `§e`、啟動儲存失敗 `§c` |

## 待確認

1. 玩家訊息前綴原本是 `[告示]`（無色），現在改為 `§7[告示]§r `；慣例允許分類前綴，但固定用 `§7[類別]§r`，請確認字樣。
2. `/sign inspect`、`/sign jobs` 的輸出是 JSON 報告，內含穩定 code（`MATCH`、`TEXT_DIFFERS`、`DONE`…），依慣例不翻譯；`msg.jobFinished` 的結束狀態也直接顯示 code。若要中文狀態字需另訂 code 對照。
3. 狀態牌（type 41）牌面文字有自己的樣式（`§r§a⦋狀態⦌§r`），不套用訊息色碼慣例。
4. `/sign set` 有兩個用法字串（`cmd.sign.usageSet`、`cmd.sign.usageSetShort`，後者來自 SignEvents 原文字 `buy|sell|type 商品代碼`），兩者不一致，原樣保留。
5. help 的 `jobs` 原本依權限顯示單行 `[cancel]`，現在拆成 `jobs` 與 `jobs cancel` 兩行，各自檢查權限。
6. 舊版 `--force` 說明與其他提示行原本帶 `[告示]` 前綴，help 內改為不帶，使用 `§7` 補充說明格式。
7. `/sign status` 與取消工作結果中原本直接顯示 `true`／`false`，現在改顯示「是／否」。
8. 玩家間提示（如 `msg.reply` 包住的例外訊息）使用 `§b` 預設色，個別 `err.ex.*` 以 `§c` 覆蓋。
